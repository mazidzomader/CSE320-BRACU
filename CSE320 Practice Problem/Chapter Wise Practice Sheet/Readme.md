# Some Error Corrections from Faculty (Damn, he is goated)
- ***Chapter 6***: There seems to be a calculator error in Q5.iii. Also, you calculated the output slot duration by dividing the frame duration by the multiplexing unit. This is wrong: you should divide the frame duration by the number of channels instead. Additionally, there is one major disadvantage of statistical TDM that you missed. In statistical TDM, the frame typically has fewer slots than the total number of channels to improve efficiency. However, if all channels are sending data at a peak hour, some slots will have to wait, since there is not enough space in the frame to allocate for all slots.

- ***Chapter 10***: The solutions look alright. I'm not sure why you skipped the questions that involve error correction using block coding. The process is simple: you calculate the Hamming distance of the given word with all the codewords. Let t be the minimum Hamming distance (with the given word) you get here. You also calculate the minimum Hamming distance between each pair of codewords, which is d_min. If d_min >= 2t + 1, then the error can be corrected, and the codeword that has t Hamming distance with the given word is the original codeword (which went through error(s)).

- ***Chapter 12***: The CSMA/CD problems are mostly okay, except for one theoretical detail: in CSMA/CD, if there is a collision, the station has to retransmit the frame. If the frame size is smaller than the minimum frame size required by CSMA/CD, the station may not be able to retransmit it if a collision occurs. This is because by the time it is able to detect that its frame has collided, it may have finished transmitting the entire frame, leaving no part of it with itself. Also, in the pure ALOHA question, B's first frame collides with A's first frame at 20 μs.
